奖励工程：一次只改一件事

实验课 · 约 10 分钟阅读 + 一晚挂机 · 前置：第 3 课

第 3 课你知道了鸭子看什么；这一课你决定它为什么而活。当前奖励是三项之和：

# microduck_brax_env.py · step()
r_tracking = exp(−((实际前进速度 − 指令vx) / 0.30)²)   # 主分：贴着指令走
r_alive    = 0.25                                      # 活着就有
r_action   = −0.005 · Σ(动作变化量²)                    # 微量平滑

记住这个事实：这三项是你接下来所有实验的操作对象。动它们之前， 先读一遍 奖励设计八诫——那是官方 团队用无数次失败训练换来的戒律，本课的每个实验都踩在其中一条上。

实验方法：基线 → 单变量 → 预测 → 验证

奖励实验最大的陷阱不是改错，而是同时改三件事然后不知道哪件起效。 流程永远是这样：

  1. 留基线：runs/smoke 就是现成基线（6.6→6.4→7.8）。
  2. 单变量：改一个常数，只一个。git diff 应该只有几行。
  3. 先写预测：动笔改之前，把"我预期奖励曲线怎么变"写在 runs/exp_名字/PREDICTION.md 里。写不出预测 = 还不理解这个项。
  4. 门禁：JAX_PLATFORMS=cpu python3 tests/test_brax_env_cpu.py。
  5. 跑冒烟：4096 步进 runs/exp_名字/，与基线并排看 CSV。
  6. 判卷：预测对了吗？对→写下为什么；错→恭喜，这是最值钱的一课， 找老师对答案。

#改动我的预测（先自己写！）踩的诫
1ALIVE_BONUS = 0.0失去"不摔也有分"，早期探索更穷……还是更快学会不摔？四：不许赖在坏状态里拿分
2TRACK_STD = 0.15高斯变窄：贴不准指令的分变少，步态更激进还是直接摆烂？七：高斯宽度=在乎的误差
3ACTION_RATE_WEIGHT = 0.05（10 倍）动作变稳、步子变小？还是干脆不动了？五：平滑税缓征
4vx 从 U(0,0.6) 改成恒 0.4任务变简单，收敛显著变快？二：字面主义
5摔倒时额外 −5 分真的能加速学会不摔吗？（官方的答案可能反直觉）三：禁止头奖的反面

本课的动手赢面：启动你的第一个奖励实验 
# 1. 改一个常数
sed -i 's/ALIVE_BONUS = 0.25/ALIVE_BONUS = 0.0/' microduck_brax_env.py
git diff --stat                    # 确认只动了这一行
# 2. 门禁 + 预测 + 冒烟
JAX_PLATFORMS=cpu python3 tests/test_brax_env_cpu.py
echo "我预测：……" > runs/PREDICTION_exp1.md
nohup python3 train_microduck_brax.py --num-timesteps 4096 \
    --episode-length 100 --num-evals 3 --out-dir runs/exp1_no_alive \
    > runs_exp1.log 2>&1 &
# 3. 明早并排判卷
column -s, -t runs/smoke/training_log.csv    | less -S
column -s, -t runs/exp1_no_alive/training_log.csv | less -S
# 4. 恢复现场（重要！）
git checkout microduck_brax_env.py

把你的预测和实际结果贴给老师，一起判卷。
