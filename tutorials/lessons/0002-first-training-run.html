跑通你的第一条训练管线

实操课 · 约 40 分钟（其中 25 分钟挂机等待） · 前置：第 1 课

这节课你要亲手跑通完整闭环：代码测试 → GPU 门禁 → 训练 → 看曲线和动画。 四条命令是每一位工程师的每日动线，跑通它们，你就"入职"了。

环境前提 source ~/robotics_env/bin/activate（activate 已自动设置 ONEAPI_DEVICE_SELECTOR=level_zero:0，把 JAX 锁到 A380 独显）， 然后 cd ~/src/github.com/pollen-robotics/microduck_rl。 验证：python3 -c "import jax; print(jax.devices())" 应输出 [OneapiDevice(id=0)]。

① 代码冒烟：30 秒，不动 GPU

JAX_PLATFORMS=cpu python3 tests/test_brax_env_cpu.py

7 个测试锁定环境的核心契约：61 维观测、奖励有限、摔倒判定、命令块零填充、 MJX 变体 XML 配置。从今天起养成纪律：改了任何环境代码，先跑它。 这和你写后端代码先跑单元测试是同一件事——它把"改挂了"的发现时间从 半小时的 GPU 训练压缩到 30 秒。

② GPU 门禁：1 分钟，验证硬件链路

python3 test_biped_mjx_batch.py 32 20 0 0

32 只鸭子各步进 20 次，期望打印 吞吐量 (FPS): 75 左右。 它的意义：把"物理仿真层"和"训练层"解耦验证。如果这步挂了， 问题在 GPU/配置；如果这步通了而训练挂了，问题在训练代码。二分定位。

③ 训练冒烟：挂机 25 分钟

nohup python3 train_microduck_brax.py --num-timesteps 4096 \
    --episode-length 100 --num-evals 3 --out-dir runs/my_smoke \
    > runs_my_smoke.log 2>&1 &
tail -f runs_my_smoke.log   # 跟踪进度，Ctrl+C 退出跟踪不影响训练

前约 4 分钟是编译 + 首次评估，之后每几分钟打印一行 eval。4096 步练不出 走路（那需要几十万步），但足以验证每个环节都在产出。参考结果： 三次 eval 奖励 6.6 → 6.4 → 7.8（我们的冒烟实测），最后一个 checkpoint 的 rollout 撑 21 步后摔倒——正常，它还是个"婴儿"。

④ 看结果

column -s, -t runs/my_smoke/training_log.csv | less -S   # 曲线数据
python3 rollout_microduck.py --replay runs/my_smoke/rollout_final.npz

GIF 会出现在 runs 目录里。--replay 模式不需要 GPU、不需要 JAX，纯 CPU 秒出——所以你可以在任何机器上向别人展示成果。

主推资源

本课操作细节的权威出处就是仓库自己的 《A380 本地开发指南》（§3 十分钟上手、 §10 故障排查表），以及 Brax 官方的 training notebook （我们封装的 train_microduck_brax.py 就是对它的工程化）。 打印一张 命令速查卡，后面每天都用。

常见新手弯路 不要为了"练快一点"把 --num-timesteps 拉到几十万就下班—— 先保证一次 4096 步的冒烟全绿，再谈加大。管线没验证过的大训练， 挂 8 小时后给你一个报错，是本课最贵的失败方式。
